# 使用与验收

## 运行依赖

Python 3.10+、NumPy、Pillow、OpenCV，以及系统 FFmpeg/ffprobe（需支持 libx264 与 AAC）。不需要 API Key、网络请求或生成模型。Python 依赖在 `scripts/requirements.txt`。

## 输出与参数

默认每张图片独立生成5秒视频、上传视频保持原时长、每输入独立MP4、保留视频第一条音轨、小狗静音。预览模式最长边不超过1280像素，高清不超过1920，source不主动缩小；不放大低分辨率原片。编码所需奇数宽高会补齐为偶数。

运行示例均从 Skill 根目录执行：

```bash
python3 scripts/render_overlay.py --inputs '/path/image.webp' '/path/movie.mp4' --output-dir temp_data/results --seed 42
```

- `--image-duration`：静态图片片长，单位秒。
- `--quality preview|hd|source`：画幅策略。
- `--seed`：控制换狗、相位和候选选位，可复现。
- `--placement-mode auto|corner`：支撑线/留白启发式，或角落策略。
- `--height-ratio`：显式覆盖默认自适应偏好；小狗动画画布高度/输出画高，可按完整动作范围缩小以适配；不是角色可见像素高度的精确比例。省略时联合比较0.24、0.22、0.20、0.18与落点，必要退化到更小尺寸并告警。
- `--anchor X Y`：归一化脚底锚点，坐标范围0–1；位置固定，边界不容纳完整角色时缩小或失败，不擅自移动指定位置。
- `--dog-id`：指定第一镜头的素材标识，后续仍按不相邻重复规则换狗。
- `--cuts '1.0,2.0'`：人工切点覆盖自动结果；空字符串表示整片一个镜头。
- `--plan-only`：只写分析计划，不生成MP4，不能把计划里的拟输出路径当成成片。
- `--music FILE`：显式替换原音轨，按成片长度循环/裁切并编码AAC；不默认替换音轨。
- `--tracking off`：首版仅支持固定落点。flow明确返回错误，不是隐藏功能。
- `--timeout`：每个FFmpeg阶段的最大运行秒数，默认600。

一次最多64个输入，首版按单worker顺序处理，避免多路编码抢资源。输出目录可复用，每次调用创建唯一任务子目录；相同文件重复上传不会覆盖输出。

## 结果契约

命令逐文件打印JSON状态，并生成每文件计划与批次summary。
每文件包含 `input、output、status、shots、timings、warnings`；每个镜头包含 `start、end、dog_id、anchor、height_ratio、phase_frames、placement`。
`output-dir/summary.json` 是最近完成任务的副本；并发调用时以最后完成者为准，隔离子目录中的summary不会丢失。

全部成功退出0，部分或全部失败退出1，参数错误退出2。失败计划保留错误信息，成功结果仍可交付。提交素材后不要只根据进程退出状态判定整个批次，读取每个文件真实状态。

## 自动化边界

- 自动分镜使用低分辨率经典硬切检测和短闪光抑制；渐变转场、摇镜、快切存在误判，使用人工切点修正。
- 视频VFR会转为CFR，帧级时长存在近似；视频旋转由解码坐标统一处理。
- 落点依据水平支撑线、纹理/显著性启发式；不保证语义主体避让、文字检测、地面理解或遮挡效果。
- 镜头位置来自代表帧，镜头内固定；移动主体和大幅运镜不跟踪，小狗可能悬浮。
- 每帧只新增一只小狗，不识别或删除原画面已有贴纸；对效果参考原片再次套用会出现原有狗加新增狗。
- 动态WebP/GIF按第一帧处理为图片，不保留其原动画；真实动画输入请转为视频后提供。
- 素材缓存随包提供。预处理耗时不算常规渲染，但首次缺依赖和缓存时需单独计时。

## 测试入口

```bash
python3 scripts/render_overlay.py --self-test
python3 scripts/test_overlay.py
```

内置系统临时目录自测使用mock透明资源，覆盖20个检查，包括EXIF、旋转、VFR、音轨、切点、短色调闪光、安全循环前缀、护栏候选、透明边缘、重复输入、超时和失败隔离；它不能替代16只真实素材的测试。
`test_overlay.py` 使用随包真实素材，生成3镜头/有声/静音竖版等固定测试输入，运行素材完整性、确定性、人工和自动切点、图片视频、音轨与坏文件回归。
运行结果保存到 `temp_data/test_results.json`；该运行产物被忽略，不纳入上传包。

## 效果检查

逐镜头检查：脚底位置是否成立、完整动作是否越界、主体是否被挡、循环是否跳帧、边缘是否绿溢色、切点是否换狗。
靠机器检查结构与时间，靠人工或专门视觉检查审美；脚本运行成功不等于选位符合每一张图。
用户觉得不合适时先换seed、改锚点和尺寸，不临时调用生成模型“修复”画面。

## 性能口径

性能从实际每文件计划 `timings` 读取，标明输入长度、画幅、机器、编码器与缓存命中情况。分开计算分析、合成/编码、素材准备和上传/下载；不能把3秒样片的速度外推为所有长视频秒级完成。

2026-11-04本容器的单次测试（CPU/libx264，FFmpeg 5.1.9，engine overlay-1.1.0，透明素材已缓存，测试时还有并行回归负载）：
- 一张真实海边参考裁切图，生成3秒、470×1280短视频，总处理1.21秒，含素材加载、编码与验证，画面分析缓存命中。
- 本次上传约21.7秒参考视频，输出1280×720/24fps，总处理10.01秒，其中画面分析1.81秒、解码叠加编码6.60秒；这是技术回归，输入已含旧贴纸，不作为“仅一只狗”的效果展示。
- 素材全量预处理约161.6秒，只需维护或缓存缺失时执行；随包包含16只透明缓存，不在常规成片处理时重复抠绿。

这些是样本计时，不是P50/P95或对任意机器的性能承诺，不包含上传/下载。自动落点已有护栏优先改进，但画面里角色抬脚及支撑线误差仍会显得悬浮，需要人工锚点修正；并非所有原素材的循环接缝无缝。

## 数据与维护

输入不会发送到生成服务。只把16只预制素材作为固定assets；用户上传素材、渲染计划、缓存、日志及结果留在任务或temp_data目录。
定期清理本地temp_data，确保仍要交付的成片先保存到用户期望位置；清理不能默默删掉正在运行的任务。

## 自适应计划与提升上限（1.2.0）

尺寸与落点共同评分，而非先定小尺寸再找线。完整RGBA画布（包含全动作周期）必须在显示画幅内，不覆盖检测人脸和人物保护框。人物保护来自随OpenCV提供的Haar人脸、经典HOG人物检测以及人脸向下扩展的人体近似框，不下载模型。图片重新取最长边640的代表图用于选位，视频仍使用低分辨率分镜代表帧；小脸、背脸、坐姿、拥挤/远处人物仍容易漏检，近似框也会误拒可用位置。

自动模式忽略上部(y<0.52)支撑线，下部留白始终与支撑候选竞争；评分包括纹理/显著性代理、下半部偏好、材料条带/垂直结构、平滑远景线和画底边框惩罚，以及较大尺寸偏好。这不是天花板/地面语义分类，也不保证每条检测线是真实承载面。corner模式保留角落策略；手动anchor不擅自移动，只允许整数像素取整误差和安全缩小，保护冲突无法解决时明确失败。

计划 `requested_height_ratio=null` 表示自适应；`shots[].height_ratio` 是最终画布像素高度/显示画高。`placement` 包含 `size_mode`、`evaluated_sizes`（尺寸、落点、联合分数）、`selection_reason`、`lower_region_cost`、支撑几何、检测保护框、`analysis_resolution`、实际源/输出素材尺寸和缩放倍率。尺寸上限可能因横竖画幅/完整周期fit而降低；不要把请求比例当作最终比例。

原生缓存避免旧384高先缩小再放大的损失；缩放仍只是重采样，不新增真实细节。本次不锐化（清单记录0），不使用生成模型或补帧。源压缩瑕疵、色溢、轮廓缺损无法凭空高清恢复。缓存来源/实际分辨率和保留动作约定见[素材来源](asset-provenance.md)。

新增回归覆盖联合自适应/保护区域缩小、手动覆盖与边界取整、放大/缩小/异向透明采样、16狗原生尺寸和源SHA、dog_06/dog_15与原片抠绿像素一致、上部结构排除、人物近似框及完整周期合成。性能仍以本次计划计时为准；原生缓存包更大，加载耗时和峰值内存比旧缓存增加。

依赖锁定 OpenCV 4.x（`opencv-python-headless>=4.8,<5`）：已实测某些5.x构建不包含CascadeClassifier/HOG及级联文件，不能把这种环境误报为已做人脸/人物检测。4.x依赖自带经典检测器，不另行下载模型；本次新增测试明确核验本地Haar/HOG可用。缺检测器的环境仍按计划告警，不承诺主体保护。相同seed复现需保留相同输入、参数、素材及依赖版本；预处理签名包括OpenCV版本。
